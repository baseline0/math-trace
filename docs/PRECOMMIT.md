# Pre-commit Hooks Guide

This document explains the pre-commit hook configuration and best practices for math-trace developers.

## What are Pre-commit Hooks?

[Pre-commit](https://pre-commit.com) is a framework that prevents commits with issues by running automated checks. Hooks run in two stages:

- **Pre-commit**: Fast checks (~1-3s) that block commit creation if they fail
- **Pre-push**: Slow checks (~5-30s) that block pushing to remote if they fail

## Setup (One-Time)

```bash
# Install the pre-commit framework and configure hooks
uv run pre-commit install --install-hooks

# Verify hooks are installed
ls -la .git/hooks/pre-commit .git/hooks/pre-push
```

## Hook Stages

### Pre-commit Stage (runs on `git commit`)

Fast checks that ensure code quality before commits:

| Hook | Priority | Purpose | Duration |
|------|----------|---------|----------|
| Whitespace trimming | P3 | Remove trailing spaces | <100ms |
| End-of-file fixer | P3 | Add/fix newline at EOF | <100ms |
| Case conflict check | P3 | Prevent case-sensitive file issues | <100ms |
| Merge conflict check | P3 | Prevent committing merge markers | <100ms |
| Mixed line ending fix | P3 | Normalize line endings | <100ms |
| TOML validation | P2 | Validate .toml files | <100ms |
| YAML validation | P2 | Validate .yaml files | <100ms |
| Ruff linter | P2 | Python linting (fixes auto) | ~500ms |
| Ruff formatter | P2 | Python formatting (fixes auto) | ~500ms |
| GitHub Actions validation | P1 | Validate workflow syntax | ~100ms |
| Secret detection | P1 | Prevent committing credentials | ~100ms |
| Large file check | P1 | Prevent huge files | ~100ms |
| Python syntax check | P1 | Validate all .py files | ~500ms |
| Autogenerated regeneration | P0 | Sync Typer-derived files | ~1s |
| Secret prevention | P0 | Block .env in src/ | <100ms |
| Dist cleanup | P0 | Block .env in dist/ | <100ms |

**Total pre-commit time**: ~3 seconds

### Pre-push Stage (runs on `git push`)

Slow checks that must pass before pushing:

| Hook | Priority | Purpose | Duration |
|------|----------|---------|----------|
| Unit tests | P0 | Run test suite | ~4-5s |

**Total pre-push time**: ~5 seconds

## Common Workflows

### Normal commit (automatic checks)

```bash
$ git add src/math_trace/server.py
$ git commit -m "fix: improve error handling"

# Pre-commit hooks run automatically:
# ✓ Whitespace trimming
# ✓ Python linting & formatting
# ✓ Secret detection
# ✓ Syntax validation
# → Commit succeeds
```

### When hooks fail

```bash
$ git commit -m "Add feature"

# ✗ Pre-commit hook failed: Ruff formatter found issues
# [P2] Format with ruff.................................................Failed

# Fixes are auto-applied to most hooks:
$ git status
# On branch main, Changes not staged for commit:
#   modified:   src/math_trace/server.py  (auto-formatted)

$ git add src/math_trace/server.py
$ git commit -m "Add feature"
# → Commit succeeds (hooks re-run, now pass)
```

### Before pushing

```bash
$ git push origin main

# Pre-push hooks run:
# [P0] Pre-push: Run unit tests........passed
# → Push succeeds
```

### When tests fail

```bash
$ git push origin main

# ✗ Pre-push hook failed: Unit tests failed
# [P0] Pre-push: Run unit tests.......FAILED
# test/unit/test_server.py::test_api_response FAILED

# Fix the test failure locally, then retry push
$ just test  # or: uv run pytest tests/unit -v
# → Fix the issue
$ git push origin main
# → Push succeeds
```

## Manual Control

### Run hooks manually

```bash
# Run all hooks on all files
uv run pre-commit run --all-files

# Run only specific stage
uv run pre-commit run --hook-stage commit     # Pre-commit hooks only
uv run pre-commit run --hook-stage push       # Pre-push hooks only

# Run specific hook
uv run pre-commit run trailing-whitespace --all-files
uv run pre-commit run ruff --all-files
```

### Regenerate autogenerated files

```bash
# Manually trigger autogeneration (normally happens in pre-commit)
just regenerate

# Or directly:
bash scripts/regenerate-autogen.sh
```

### Bypass hooks (not recommended)

```bash
# Skip pre-commit hooks (for emergencies only)
git commit --no-verify -m "Emergency fix"

# Skip pre-push hooks (strongly discouraged)
git push --no-verify

# Better alternative: Fix the underlying issue
just test  # Debug why tests fail
# Then push normally (hooks will pass)
```

## Hook Configuration

The hook configuration is in `.pre-commit-config.yaml`. Structure:

```yaml
default_install_hook_types:
  - pre-commit    # ← Install pre-commit hooks
  - pre-push      # ← Install pre-push hooks

repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    # Standard checks (whitespace, syntax, etc.)
  
  - repo: https://github.com/astral-sh/ruff-pre-commit
    # Python linting & formatting
  
  - repo: local
    hooks:
      - id: just-test-unit
        name: "[P0] Pre-push: Run unit tests"
        stages: [pre-push]  # ← Runs only on pre-push
```

**Priority naming convention**:
- `[P0]` Critical: Safety and architecture
- `[P1]` High: Code quality and governance
- `[P2]` Medium: Style and formatting
- `[P3]` Low: Whitespace and hygiene

## Fleet-wide Consistency

```bash
# Check your repo
```

## Troubleshooting

### Hooks run too slowly

Pre-commit checks should take <5 seconds total. If they're slow:

1. **Check which hook is slow**:
   ```bash
   uv run pre-commit run --all-files -v
   ```

2. **Profile slow hooks**:
   ```bash
   time uv run pre-commit run ruff --all-files
   ```

3. **Optimize or move to pre-push**:
   - Custom hooks: check for inefficient shell scripts
   - Linting: check for large file sets (see `files:` exclusion patterns)

### Hooks not running

```bash
# Verify hooks are installed
ls -la .git/hooks/

# Reinstall if needed
uv run pre-commit install --install-hooks

# Check configuration
uv run pre-commit validate-config .pre-commit-config.yaml
```

### Merge conflicts in `.pre-commit-config.yaml`

Rarely happens, but if it does:

```bash
# Resolve conflict manually, then:
git add .pre-commit-config.yaml
git commit -m "resolve: merge conflict in precommit config"

# Verify it's valid:
uv run pre-commit validate-config .pre-commit-config.yaml
```

### "Hook id not found" error

```
# ✗ Error: Hook id "my-hook" not found in local repo
```

This means the hook is defined in the config but not implemented. Check `.pre-commit-config.yaml` and either:
- Remove the hook definition if it's no longer needed
- Implement the hook script if it should exist

## Best Practices

### 1. Don't bypass hooks

✅ **Good**: Fix the underlying issue
```bash
$ git commit
# ✗ Tests fail in pre-push
$ just test  # Run tests, fix the failure
$ git push
```

❌ **Bad**: Use `--no-verify` as a habit
```bash
$ git push --no-verify  # Weak!
```

### 2. Keep hooks fast

Pre-commit hooks should run in <5 seconds total. If adding a new hook:
- Use `stages: [pre-push]` for slow operations
- Use `files:` pattern to limit scope
- Optimize shell scripts

### 3. Use `always_run: true` for critical checks

```yaml
- id: just-test-unit
  always_run: true  # ← Runs even if no files changed
```

### 4. Configure exclusions carefully

```yaml
- id: ruff
  exclude: |  # ← Skip vendored or generated code
    (?x)^(
      vendor/|
      generated/
    )
```

### 5. Document custom hooks

```yaml
- id: my-custom-check
  name: "[P1] My custom check"  # ← Priority tag helps others understand
  entry: bash scripts/my-check.sh
```

## Adding New Hooks

To add a new hook to math-trace:

1. **Edit `.pre-commit-config.yaml`**:
   ```yaml
   - id: my-new-hook
     name: "[P1] My new check"  # ← Include priority tag
     entry: bash scripts/my-check.sh
     language: system
     stages: [pre-commit]  # or [pre-push] if slow
     pass_filenames: false
   ```

2. **Create the script** (`scripts/my-check.sh`):
   ```bash
   #!/bin/bash
   # Brief description
   # Exit 0 if ok, 1 if failure
   ```

3. **Make it executable**:
   ```bash
   chmod +x scripts/my-check.sh
   ```

4. **Test the hook**:
   ```bash
   uv run pre-commit run my-new-hook --all-files
   ```

5. **Commit the changes**:
   ```bash
   git add .pre-commit-config.yaml scripts/my-check.sh
   git commit -m "feat: add pre-commit hook for my-new-check"
   ```
